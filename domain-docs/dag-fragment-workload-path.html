Executive Read // workload pairing

This path converts the domain languages of the Critical Path ontology into ordered, markable workloads. Every workload is stated only in domain terms. Completing a lower layer unlocks the next language. No workload may introduce mutation of history or bypass Projection as the sole readable surface.

Substrate Workloads → Fragment Workloads → Contract Workloads → Bucket Workloads → Composition → Antenna

Antenna Workloads // federation readiness

highest language · least description

Confirm that composition yields a single measurable critical-path length across joined Fragments. Only then open federation of independently projected substrates.

Composition Workloads // join readiness

fragment assembly · brief

Declare the Projection shape that results when two Fragments attach at matching Contracts. Verify the joined graph remains acyclic and that critical-path length is the longest path across the attachment. No new mutation language is introduced; composition is read-only over existing Edges.

Bucket Workloads (0/4)

constraint domains that gate emission

Buckets are versioned constraint facts. A workload is complete when the named domain exists, can be evaluated against a proposed Edge, and either refuses or permits emission without ever rewriting prior Events.

✓
Name the first constraint domains
Declare at least SLA horizon, residual capacity, and permission set as distinct Bucket identities. Each Bucket is a fact, not a process step.
✓
Bind evaluation to Edge emission
Before any Edge is appended, the relevant Buckets are consulted against the proposed Edge properties and the current Projection of the participating Nodes.
✓
Refusal leaves history untouched
A failed Bucket evaluation produces no Event, no Edge, and no Projection change. Success produces the triple atomically.
✓
Bucket versions are themselves facts
Constraint values may change over time only by recording a new versioned fact. Prior evaluations remain reconstructible from the Event stream.

Contract Workloads (0/4)

port interfaces at Fragment boundaries

A Contract is the only legal surface at which two Fragments may later join. Workloads formalize the boundary before any composition is attempted.

✓
Identify boundary Nodes inside the seed Fragment
Mark which Nodes of the existing WorkOrder Fragment may serve as ports for future attachment. Internal Nodes remain private to the Fragment.
✓
Declare allowed crossing Edge types
Name the Edge types that may leave or enter a Fragment at a Contract. All other Edge types are forbidden from crossing.
✓
Specify Projection shape required at the join
State which Projection facts must remain consistent on both sides of a Contract after attachment. Consistency is checked by Projection comparison, never by rewriting history.
✓
Treat Contract as annotation until composition is required
Until a second Fragment exists, a Contract is simply a typed declaration on the boundary Nodes. No additional mutation language is introduced.

Fragment Workloads (0/6)

primary unit of scale · self-contained DAG

A Fragment is born by emission of a typed creation Edge, owns a contiguous Event slice, and exposes zero or more Contracts. These workloads make the seed WorkOrder recognizable as the first Fragment and establish the pattern for every subsequent Fragment.

✓
Designate the root Node of the seed Fragment
The WorkOrder Node already present is declared the root. All other Nodes and Edges of the Fragment are reachable from this root by directed paths.
✓
Bind the Fragment to a contiguous Event slice
Every Event belonging to the Fragment is identifiable by stream identity or correlation so that the Fragment can be replayed in isolation.
✓
Confirm the first Projection is keyed by the root
The existing current-state Projection is recognized as the Fragment’s primary readable surface. No second source of current truth is permitted.
✓
Treat creation Edge emission as the sole birth act
A new Fragment comes into existence only by appending a typed creation Edge and its matching Event. Schema mutation is never the birth mechanism.
✓
Keep internal Edges private to the Fragment
Edges that do not appear in any Contract declaration never leave the Fragment boundary. Cross-Fragment contact is deferred until Contract workloads are complete.
✓
Derive critical-path length as a Projection, never as mutable state
Longest-path length inside the Fragment is computed from the Edge set and stored only as a derived Projection. It is never updated in place.

Substrate Workloads (0/10)

now · infrastructure readiness · highest priority

These workloads make the four substrate relations operationally true and observable. They are the only work that may proceed before Fragment formalization. Every higher language depends on their completion.

Identity and Contact

(0/3)
✓
Verify every process participant is a typed Node
Confirm that WorkOrder, and any future actor or state holder, exists only as a Node with stable identity, declared type, and properties. No process step is encoded inside a Node.
✓
Confirm every transition is a typed Edge
Creation, approval, assignment, consumption, and notification each appear solely as an Edge linking two Nodes, carrying correlation and causation identifiers.
✓
Refuse any contact that is not an Edge
Direct mutation of Node properties to represent process progress is disallowed. Progress is expressed only by additional Edges.

History and Truth

(0/3)
✓
Guarantee the Event log is append-only
Every Edge emission produces a corresponding Event. No Event is updated or removed. Replay of the Event stream must reconstruct every Projection exactly.
✓
Enforce Projection as the sole readable current truth
All consumers—analytics, future Contracts, future Buckets—read only from Projections. Direct Event interrogation is reserved for audit and reconstruction.
✓
Lock character against mutation of history
No future language may issue an in-place change to an existing Event or historical Edge. All change is additional Edges and Events; Projections are derived.

Observability and Proof

(0/4)
✓
Prove the seed closed loop is live
A WorkOrder Node, its creation Edge, the matching Event, and the Projection row exist and are jointly queryable. This is the minimal proof the four relations cooperate.
✓
Confirm substrate reachability from every host consumer
The same substrate answers every authorized consumer without translation. Ordered edge streams remain reserved capacity and are not yet required for domain correctness.
✓
Establish that replay regenerates the Projection
From the Event stream alone it is possible to rebuild the current-state Projection. This capability is the operational definition of append-only character.
✓
Declare substrate readiness complete
When all preceding substrate workloads are true, the domain is ready for Fragment formalization. No higher language may begin before this declaration.

Deliverable Horizon // upward drive

The immediate deliverable is a substrate whose seven (now ten) domain invariants are observably true, followed by recognition of the seed WorkOrder as the first Fragment. That recognition is itself a domain act: designation of root, binding of Event slice, and confirmation that the existing Projection is the Fragment’s primary surface.

Only after that deliverable is green do Contract annotations become useful. Only after Contracts exist do Bucket evaluations gain attachment points. Composition and federation remain speculative until the lower languages produce a measurable critical-path length that can be trusted across Fragment boundaries.

Invariants That Constrain Every Workload // non-negotiable

  • Every business action becomes a typed Edge.
  • Projections are the only surface for current truth.
  • Buckets gate Edges before they are written; they never rewrite history.
  • Fragments are born by creation Edges, never by schema mutation.
  • Contracts are the sole legal crossing points between Fragments.
  • Composition is a Projection over existing Edges, never a new mutation language.
  • Replay remains free: any Projection can be rebuilt from its Event stream.
